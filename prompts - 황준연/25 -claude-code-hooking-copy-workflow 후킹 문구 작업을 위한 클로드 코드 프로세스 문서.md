# 클로드 코드 활용 가이드: 최고 품질 후킹 문구 제작 프로세스

## 목표
클로드 코드를 활용하여 **하이엔드급 후킹 문구(Hooking Copy)**를 체계적으로 제작하는 8단계 워크플로우

---

## 📋 8단계 작업 프로세스

### 1단계: 프로젝트 정의 문서 작성
**목적**: 원하는 결과물을 명확하게 정의

**작성 내용**:
- 후킹 문구의 목적 (예: 메타 광고, 랜딩페이지, 웨비나 제목 등)
- 타겟 고객 페르소나 (연령, 직업, 고민, 욕구)
- 핵심 메시지 (전달하고 싶은 가치 제안)
- 톤앤매너 (진지함, 유머, 긴박함, 공감 등)
- 금기사항 (피해야 할 표현, 단어)
- 성공 기준 (클릭률 목표, 감정 반응 등)
- 참고 사례 (잘 된 후킹 문구 예시)
- 제약사항 (글자수, 플랫폼 규격)

**산출물**: `project-definition.md`

---

### 2단계: 컨텍스트 파악
**목적**: 이전 맥락과 참고 자료를 충분히 이해

**확인 사항**:
- 이전에 사용했던 후킹 문구 및 성과 데이터
- 경쟁사/벤치마크 문구 분석 자료
- 타겟 고객 리서치 자료 (설문, 인터뷰, 리뷰)
- 제품/서비스 핵심 특징 및 차별점
- 브랜드 가이드라인 및 기존 메시징
- 과거 A/B 테스트 결과

**활동**:
- 모든 참고 파일 읽기
- 핵심 인사이트 추출
- 패턴 및 트렌드 파악

**산출물**: `context-analysis.md`

---

### 3단계: 필요한 서브에이전트 카테고리 기획
**목적**: 작업을 효율적으로 분담할 전문 서브에이전트 정의

**후킹 문구 제작을 위한 서브에이전트 예시**:

1. **카피라이팅 전략가 (Copywriting Strategist)**
   - 고객 심리 분석
   - 메시지 포지셔닝
   - 차별화 포인트 도출

2. **헤드라인 크리에이터 (Headline Creator)**
   - 다양한 헤드라인 공식 적용
   - 호기심 유발 문구 생성
   - 긴박감/FOMO 표현

3. **감정 분석가 (Emotional Analyzer)**
   - 문구의 감정적 임팩트 평가
   - 타겟의 감정 버튼 매칭
   - 공감도 측정

4. **데이터 최적화 전문가 (Data Optimizer)**
   - A/B 테스트 설계
   - 성과 예측 모델링
   - 개선 방향 제시

5. **플랫폼 적응 전문가 (Platform Adapter)**
   - 플랫폼별 최적화 (메타, 구글, 네이버 등)
   - 규격 및 정책 준수 검토
   - 시각 요소 연계 제안

6. **언어 세련화 전문가 (Language Refiner)**
   - 문법 및 어감 최적화
   - 불필요한 단어 제거
   - 리듬감 조정

**산출물**: `subagent-categories.md`

---

### 4단계: 시스템 프롬프트 메이커 서브에이전트 생성
**목적**: 하이엔드급 아웃풋을 보장하는 시스템 프롬프트 제작 전문가 생성

**시스템 프롬프트 메이커의 역할**:
- 각 서브에이전트의 전문성을 극대화하는 프롬프트 설계
- 아웃풋 품질 기준 명시
- 작업 프로세스 및 체크리스트 포함
- 예시 및 템플릿 제공
- 제약사항 및 가이드라인 반영

**시스템 프롬프트 메이커가 만들어야 할 요소**:
```
- 역할 정의 (Role Definition)
- 전문성 영역 (Expertise Areas)
- 작업 목표 (Objectives)
- 프로세스 단계 (Process Steps)
- 품질 기준 (Quality Criteria)
- 아웃풋 포맷 (Output Format)
- 제약사항 (Constraints)
- 베스트 프랙티스 (Best Practices)
- 참고 예시 (Examples)
```

**산출물**: `system-prompt-maker-agent.md`

---

### 5단계: 전문 서브에이전트 생성
**목적**: 3단계에서 기획한 각 서브에이전트를 4단계의 메이커를 활용하여 생성

**프로세스**:
1. 시스템 프롬프트 메이커에게 각 서브에이전트 프롬프트 제작 요청
2. 생성된 프롬프트 검토 및 피드백
3. 최종 프롬프트 확정
4. 각 서브에이전트 파일로 저장

**주의사항**:
⚠️ 만약 4단계에서 만든 시스템 프롬프트 메이커를 현재 세션에서 즉시 활용할 수 없다면:
- **작업 일시 중지**
- **세션 재시작 요청**
- 새 세션에서 생성된 프롬프트 로드 후 진행

**산출물**: 
- `agent-copywriting-strategist.md`
- `agent-headline-creator.md`
- `agent-emotional-analyzer.md`
- `agent-data-optimizer.md`
- `agent-platform-adapter.md`
- `agent-language-refiner.md`

### 6단계: 작업 플래닝
**목적**: 최종 후킹 문구 완성까지의 작업 순서 설계

**플래닝 예시**:

```
Phase 1: 전략 수립
├─ Task 1: 카피라이팅 전략가 - 고객 심리 및 메시지 전략 수립
└─ Task 2: 감정 분석가 - 타겟 감정 버튼 매핑

Phase 2: 초안 생성
├─ Task 3: 헤드라인 크리에이터 - 30개 후킹 문구 초안 생성
└─ Task 4: 플랫폼 적응 전문가 - 플랫폼별 변형안 제작

Phase 3: 분석 및 선별
├─ Task 5: 감정 분석가 - 각 문구 감정 임팩트 평가
├─ Task 6: 데이터 최적화 전문가 - 성과 예측 및 순위 매기기
└─ Task 7: 언어 세련화 전문가 - 상위 10개 문구 정제

Phase 4: 최적화 및 완성
├─ Task 8: CEO 검토 및 피드백
├─ Task 9: 최종 3개 안 선정 및 정교화
└─ Task 10: A/B 테스트 설계 및 모니터링 계획 수립
```

**산출물**: `work-plan.md`

### 7단계: 태스크 생성
**목적**: 플래닝한 작업을 실행 가능한 구체적 태스크로 변환

**태스크 포맷**:
```markdown
## Task [번호]: [태스크 명]

### 담당 서브에이전트
[에이전트 이름]

### 목표
[이 태스크로 달성하고자 하는 것]

### 인풋
- [필요한 자료/정보]

### 프로세스
1. [구체적 작업 단계]

### 아웃풋
- [산출물 형태]
- [품질 기준]

### 체크리스트
- [ ] [확인 항목 1]
- [ ] [확인 항목 2]

### 다음 태스크 연계
[이 태스크 결과물이 어떻게 활용되는지]
```

**산출물**: `tasks.md` (모든 태스크를 포함한 마스터 문서)

---

### 8단계: 태스크 실행 및 CEO 검토 프로세스
**목적**: 각 태스크를 수행하고 단계별로 CEO의 의사결정 받기

**실행 프로토콜**:

#### 각 태스크 실행 시:

1. **태스크 시작 보고**
   ```
   📌 Task [번호] 시작: [태스크 명]
   - 담당: [서브에이전트]
   - 예상 소요 시간: [시간]
   ```

2. **중간 결과 보고**
   ```
   📊 중간 결과물:
   [생성된 아웃풋 요약]
   
   💡 주요 발견사항:
   - [인사이트 1]
   - [인사이트 2]
   ```

3. **CEO 의사결정 요청 문서 작성**
   ```markdown
   # CEO 의사결정 요청서 - Task [번호]
   
   ## 현재 상황
   [작업 진행 상황 요약]
   
   ## 제시 옵션
   
   ### 옵션 1: [이름]
   - **장점**: 
   - **단점**: 
   - **예상 결과**: 
   - **예시**: 
   
   ### 옵션 2: [이름]
   ...
   
   (최소 3개 이상의 옵션 제시)
   
   ## 질문 리스트 (최소 10개)
   
   ### 전략 방향
   1. [질문]
   2. [질문]
   
   ### 메시지 톤
   3. [질문]
   4. [질문]
   
   ### 타겟팅
   5. [질문]
   6. [질문]
   
   ### 실행 방안
   7. [질문]
   8. [질문]
   
   ### 리스크 관리
   9. [질문]
   10. [질문]
   
   (추가 질문들...)
   
   ## 권장사항
   [AI의 분석 기반 추천]
   
   ## 다음 단계
   CEO 결정 후 진행될 작업
   ```

4. **CEO 피드백 반영**
   - CEO 답변 문서화
   - 피드백 기반 수정 작업
   - 수정 결과 재보고

5. **태스크 완료 보고**
   ```
   ✅ Task [번호] 완료
   - 최종 산출물: [링크/파일명]
   - 소요 시간: [실제 시간]
   - 다음 태스크: Task [번호]
   ```

**산출물** (태스크별):
- `task-[번호]-output.md` (작업 결과물)
- `task-[번호]-ceo-decision.md` (CEO 의사결정 요청서)
- `task-[번호]-feedback.md` (CEO 피드백 및 수정사항)

## ✨ 핵심 원칙

### 1. 하이엔드 품질 기준
- 단순 아이디어 나열이 아닌, 깊이 있는 분석과 전략 포함
- 모든 제안은 데이터와 심리학 원칙에 기반
- 실행 가능성과 측정 가능성 확보

### 2. CEO 중심 의사결정
- 태스크마다 명확한 옵션과 질문 제시
- 최소 10개 이상의 고민 포인트 제공
- 여러 각도의 시나리오 분석

### 3. 반복적 개선
- 각 단계마다 피드백 수렴
- 지속적인 최적화 사이클
- 학습과 개선 문서화

### 4. 전문가 수준 협업
- 각 서브에이전트의 전문성 극대화
- 명확한 역할 분담과 책임
- 시너지 효과 창출

## 📝 사용 예시: 메타 광고 후킹 문구 제작

### 1단계 예시
```markdown
# 프로젝트 정의: 책 쓰기 코칭 메타 광고

## 목적
책을 쓰고 싶지만 시작하지 못하는 예비 저자를 유입시키는 메타 광고 후킹 문구

## 타겟
- 연령: 35-55세
- 직업: 전문직, 사업가, 강사
- 고민: 책을 쓰고 싶지만 시간/노하우 부족
- 욕구: 저자로서의 권위, 수익 창출, 지식 전달

## 핵심 메시지
"3개월 만에 당신의 책을 출간하고 저자로서의 삶을 시작하세요"

...
```

## 🚀 시작하기

이 문서를 클로드 코드 세션에 로드하고:

1. 1단계 작업 시작 요청
2. 각 단계 완료 후 다음 단계 진행 요청
3. CEO 의사결정 필요 시 문서 검토 및 답변 제공

**템플릿 활용**: 각 단계의 산출물 포맷을 그대로 사용하여 일관성 확보
